# Repository conventions

## User and project conventions take priority

- Follow explicit user instructions and the repository's existing conventions before any agent, tool, or product default.
- Never add `codex`, `codex-`, `codex/`, or another agent/tool attribution to branch names, commit messages, stash names, pull requests, tags, filenames, temporary labels, or generated content unless the user explicitly requests it.
- Use the repository's existing branch style such as `feat/<topic>`, `fix/<topic>`, or `chore/<topic>`.
- Use the repository's existing commit style such as `feat:`, `fix:`, `chore:`, `docs:`, `test:`, and `refactor:`.
- Give temporary work descriptive, task-specific names without agent attribution, for example `pre-main-merge-YYYYMMDD`.
- If the applicable project convention is unclear, inspect nearby examples first and ask the user before inventing a new convention.
