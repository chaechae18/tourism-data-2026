# 보안 검토 — 2026-09-20

현재 코드에 **배포 전 우선 조치가 필요한 보안 문제가 있습니다.** 가장 큰 문제는 사용자 식별을 로그인 세션 대신 외부 요청 헤더에 맡긴 장소 API입니다. 이 문서는 발견·재현 결과이며, 아래 애플리케이션 취약점은 **미수정** 상태입니다. 이번 변경은 레드팀 코드·실행기·보고서와 테스트 분리 설정입니다.

범위는 로컬 작업 트리입니다. 운영 DB·실제 계정·배포된 사이트에는 공격 요청을 보내지 않았습니다. 자동 검사 개수와 관찰값은 [실행 보고서](report.md), 패키지 버전은 [의존성 보고서](dependency-audit.json)를 기준으로 합니다. 같은 원인으로 여러 시나리오가 실패하므로 실패 개수는 서로 다른 취약점 수와 같지 않습니다.

## 우선 수정할 항목

### RT-01 · Critical · 사용자 번호 헤더로 계정 사칭과 글 삭제

- 위치: `backend/app/routers/spots.py`, `interactions.py`, `uploads.py`, `translations.py`; `frontend/lib/api/spots.js:3`, `translations.js:5`.
- 인증 쿠키 없이 `X-User-No: 1`만 보내도 글·댓글 작성, 좋아요, 자신의 글 목록 조회, 이미지 업로드, 번역이 성공했습니다. 가짜 계정 1의 글 삭제는 HTTP 204와 실제 `DELETED_AT` 변경으로 확인했습니다. 사용자 2의 유효 세션이 있어도 사용자 1 헤더를 보내면 사용자 1의 글을 삭제할 수 있었습니다.
- 미승인 댓글 또한 소유자 번호 헤더를 보내면 조회됩니다. 프론트는 모든 사용자의 요청에 고정 번호 1을 보냅니다. 기존 작성 내역을 실제 작성자에게 자동 재배정할 근거는 없습니다.
- 수정: 쓰기·개인 조회 API는 `get_current_user`로 검증한 세션의 사용자 번호만 사용합니다. 공개 목록의 선택적 사용자 정보도 세션에서만 가져옵니다. 프론트의 고정 번호를 제거하고 `credentials: "include"`를 함께 적용해야 합니다. 기존 글의 소유권 변경은 별도 데이터 확인이 필요합니다.
- 재현: `test_spot_routes_reject_anonymous_impersonation`, `test_signed_in_user_cannot_delete_another_users_spot`, `test_pending_comment_cannot_be_read_by_spoofing_owner`.

### RT-02 · High · 탈퇴한 계정의 방문 기록 조회

- 위치: `backend/app/routers/auth.py:get_visit_places`.
- 탈퇴 전에 복사한 쿠키로 `/auth/me`, 코스 API는 401을 반환하지만 `/auth/visit-place`는 200을 반환합니다. 계정 상태를 확인하지 않고 세션 사용자 번호와 언어만 조회하기 때문입니다.
- 테스트는 접근 허용을 재현했습니다. 테스트 계정의 방문 기록은 비어 있으며, 기존 기록 노출 영향은 코드의 조회 조건에 근거한 판단입니다.
- 수정: 방문 기록도 공통 활성 사용자 인증 의존성을 사용합니다.

### RT-03 · High, 설정 조건부 · 빈 세션 비밀키 허용

- 위치: `backend/app/config.py:get_settings`, `backend/app/main.py:59`.
- `SESSION_SECRET_KEY`가 없거나 빈 값이어도 설정 로딩이 성공하고 그 값을 세션 서명에 전달합니다. 이 설정으로 배포하면 알려진 빈 키로 쿠키 위조가 가능합니다.
- **현재 운영 비밀키가 비어 있다는 뜻은 아닙니다.** 테스트 전용 빈 환경으로 설정 검증 누락을 확인했습니다. 정상 임의 키로 구성한 이번 실행에서는 빈 키·잘못된 키·과거 개발 기본키로 서명한 쿠키가 모두 거부됐습니다.
- 수정: 비밀키 미설정 시 시작을 중단하고 충분히 긴 임의 키만 허용합니다. 과거 공개된 키를 사용 중인 환경은 교체합니다.

### RT-04 · High · 로그인 요청의 Origin·콘텐츠 타입 검증 없음

- 위치: `backend/app/routers/auth.py:create_login`.
- 공격자 Origin과 `Content-Type: text/plain`을 보낸 JSON 로그인 요청도 HTTP 200으로 처리됩니다. 로그인 함수만 유효한 가짜 계정 결과로 대체해 HTTP 경계의 누락을 재현했습니다. CORS 응답 읽기 제한은 서버의 로그인 처리를 차단하지 않습니다.
- 영향: 조건이 맞는 브라우저에서 공격자 계정으로 로그인 상태를 바꾸는 로그인 CSRF 가능성. 실제 브라우저에서 쿠키가 저장되는 끝단 공격은 별도 검증이 필요합니다.
- 수정: 로그인·회원가입을 포함한 상태 변경 요청에 허용 Origin 검증 또는 CSRF 방어를 적용하고 JSON 콘텐츠 타입을 검증합니다. localhost와 배포 주소의 정상 요청 대조 테스트도 추가합니다.

### DEP-01 · Critical 권고 포함 · 프론트 운영 의존성

`npm audit --omit=dev --json`에서 **4개 패키지(critical 1, high 3)**가 보고됐습니다. 이는 패키지 단위 집계이며 서로 다른 공격 4건이라는 뜻이 아닙니다.

| 패키지 | lockfile 버전 | 권고 등급 |
|---|---|---|
| next | 15.5.20 | critical |
| sharp | 0.34.5 | high |
| next 내부 postcss | 8.4.31 | high |
| nanoid | 3.3.15 | high |

Next.js 이미지 최적화의 AVIF 처리 관련 [공식 권고 GHSA-2xp9-vwfh-vxw4](https://github.com/vercel/next.js/security/advisories/GHSA-2xp9-vwfh-vxw4)는 15.x 수정 버전으로 **15.5.24**를 명시합니다. 이는 해당 권고의 수정 버전이며 다른 모든 권고 해소를 보장하는 최종 업그레이드 버전은 아닙니다. `next/image`를 쓰는 컴포넌트가 있으나 악성 이미지 도달 가능성·배포 이미지 최적화 구성은 검증하지 않았습니다.

별도의 [Windows 한정 RCE 권고](https://github.com/vercel/next.js/security/advisories/GHSA-p293-qw3h-jr36)는 조건을 구분해야 합니다. Windows 실행 조건을 Vercel·Linux Docker에도 그대로 적용해 실제 원격 실행이 입증됐다고 해석하면 안 됩니다. 실제 악성 파일이나 RCE 공격은 실행하지 않았습니다.

수정: 지원되는 패치 버전으로 Next.js와 관련 의존성을 갱신하고 lockfile, 빌드, 기능 테스트, audit를 함께 검증합니다. 이번 검토에서 패키지 버전은 변경하지 않았습니다. Python 로컬 가상환경 32개 패키지는 `pip-audit`에서 알려진 취약점 0건이었습니다. 배포 환경 버전과 일치하는지는 별도 확인 대상입니다.

## 정적 검토에서 확인한 잔여 위험

- **유료 API 비용 통제:** 번역 API는 위 RT-01 인증 문제가 있고, 도슨트 음성 API는 공개 호출이며 자체 요청량·비용 한도 검사가 없습니다. 캐시는 있지만 서로 다른 장소·언어·서버리스 인스턴스에서는 외부 호출이 늘 수 있습니다. 실제 API 비용을 발생시키는 검사는 하지 않았습니다.
- **콘텐츠 검수:** `temporary_spot_approval.py`가 10초 뒤 모든 대기 글을 임시 승인합니다. 프론트의 금지어 검사를 우회한 직접 API 요청에 서버 검수와 동일한 보호가 있다고 볼 수 없습니다. 승인 정책은 제품 판단이 필요합니다.
- **개인정보 로그:** OAuth 콜백에 `NAVER USER`, `KAKAO USER`, `GOOGLE USER` 전체 객체 출력이 있습니다. 실제 로그 수집·노출 범위는 확인하지 않았습니다. 필요한 식별 정보만 남기거나 마스킹하는 수정이 필요합니다.
- **AI 번역:** 사용자 텍스트를 JSON으로 별도 user 메시지에 전달하고 시스템 메시지를 분리하지만, 실제 모델에 대한 인젝션 공격은 검증하지 않았습니다. 이번 번역 테스트는 인증·공개 범위·호출 여부만 다룹니다.
- **비밀 파일:** 현재 Git 추적 파일에는 실제 `.env`·인증서·개인키 파일이 없었습니다. 일부 알려진 키 형식의 현재 추적 소스 검색에서도 후보가 없었습니다. 전체 과거 Git 이력과 배포 환경변수 검토를 대체하지 않습니다.

## 확인된 방어

세션 기반 개인 API의 익명 접근 거부, 잘못 서명된 쿠키 거부, OAuth state 누락·불일치 거부, 관리자 키 검사, SQL 문자열 매개변수 처리, 위장 HTML/SVG 업로드 거부, 업로드 크기·파일명 제한, 미승인 글 번역 차단, 타인 퀘스트·알림 접근 제한, 미보유 착장 거부, 보상 재전송·동시 요청의 중복 방지를 확인했습니다. 정상 회원가입·로그아웃 대조군과 외부 연결 차단 검사도 포함합니다.

우선순위는 **RT-01 → RT-02·03·04 및 DEP-01 → 나머지 세션·입력·비용·시연 정책**입니다. 수정 완료 후 일반 테스트와 레드팀을 재실행하고, 배포 반영 여부는 별도로 확인해야 합니다.
